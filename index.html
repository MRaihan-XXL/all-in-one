How it works

Three steps, zero config files to maintain. Re-run aio any time — writes are idempotent and versioned.

STEP 1 — SCAN

Reads your machine

Finds your cloned repos, tool registry and skill folders — including tools.db and TOOLS-INDEX.md.

STEP 2 — WRITE

Injects the blocks

Inserts a marked auto-config block into each agent's instructions file and generates one shared manifest.

STEP 3 — USE

Every prompt is wired

Agents read the manifest automatically and route to local tools first. Disclosure of usage is mandatory.

Usage, disclosed

The moment an agent uses an entry from your manifest, its answer starts with a markdown link back to the source — attributable, auditable, first line, every time.

# the rule aio writes into every agent + the manifest itself
[aio] Using [<name>](<url>) (<type>) — <function>

# real output, verbatim from a live agent session
[aio] Using [Stirling-PDF](https://github.com/Stirling-Tools/Stirling-PDF) (repo) — HTML/CSS/JS to PDF converter

What you get

One flat package, no runtime dependencies, Node ≥ 22. Everything reversible.

FR1One manifest, every agent

aio-context.md — repos, tools, skills, detected agents — a single source of truth all CLIs share.

FR2Idempotent + rollback

Blocks are marked and versioned; re-running never duplicates, rollback removes cleanly. No telemetry — every write is timestamped in ~/.aio/backups.

FR6Mandatory disclosure

The hard rule: any usage of a manifest entry must start the reply with the [aio] Using … link line.

FR7MCP auto-wire

Registers codebase-memory-mcp where supported, with a ledger so it is added exactly once.

NFRZero dependencies

Plain Node stdlib — sqlite via node:sqlite, tests via node --test, nothing to audit.

U6Public & traceable

GPL-3.0 on GitHub, published on npm as aio-connect, changelog in conventional commits.
